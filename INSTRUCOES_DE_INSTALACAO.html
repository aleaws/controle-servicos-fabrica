Conectar computador e tablet/celular

Use o mesmo endereço do aplicativo independente em todos os aparelhos.

1. Atualize o aplicativo

  1. No app atual, abra Dados → Exportar backup. Guarde o JSON no computador.
  2. Extraia este ZIP. No GitHub, abra controle-servicos-fabrica.
  3. Em Adicionar arquivo → Carregar arquivos, envie os arquivos extraídos e a pasta icons, substituindo os de mesmo nome. O index.html deve ficar na raiz. Confirme a alteração.
  4. Aguarde a publicação. Feche todas as janelas e o aplicativo instalado; abra novamente com internet.
  5. Em Dados, confira o título Conexão entre aparelhos • versão 2. Se ainda aparecer a tela antiga, feche tudo novamente e reabra.

Mantenha os nomes dos arquivos. Não apague os dados do navegador nem desinstale o app. Não envie backups JSON ao GitHub. Não altere o repositório do V25.

2. Prepare o Supabase — uma vez

  1. Entre no seu projeto em Supabase.
  2. Abra SQL Editor → New query (Editor SQL → Nova consulta).
  3. Abra CONFIGURAR_SUPABASE.sql deste pacote no Bloco de Notas. Copie todo o conteúdo para a consulta.
  4. Clique em Run (Executar). Aguarde o sucesso. Se aparecer erro, confira a mensagem antes de seguir.

O script cria apenas as tabelas/função fabrica_aw_*_v2. Não altera tabelas do V25 nem usa a antiga tabela de demonstração.

3. Crie a conta de conexão

  1. No mesmo projeto: Authentication → Users → Add user → Create new user (Autenticação → Usuários → Adicionar usuário → Criar).
  2. Use seu e-mail e defina uma senha. Se houver Auto Confirm User, marque. Caso contrário, confirme o e-mail conforme a indicação do painel.
  3. Guarde esses dados. Use a mesma conta nos aparelhos autorizados.

Essa conta fica dentro do projeto. É diferente da conta do painel do Supabase, da conta do ChatGPT e da senha administrativa do app.

4. Conecte primeiro o computador

  1. No Supabase, abra Connect para localizar a URL do projeto e a chave pública. A chave também fica em Settings → API Keys.
  2. No app, em Dados, preencha a URL https://SEU-PROJETO.supabase.co, a chave publishable ou anon e a sala FABRICA-AW.
  3. Clique em Salvar configuração. Não use chave secreta nem service_role.
  4. Preencha o e-mail e a senha da etapa 3. Clique em Entrar e sincronizar.
  5. Aguarde Sincronizado — sala FABRICA-AW. Os registros locais serão enviados ao novo banco.

Se a sala já contiver dados incompatíveis, o app pede revisão em vez de substituir tudo automaticamente.

5. Conecte o tablet/celular

  1. Abra o mesmo endereço online do app. Não abra uma cópia HTML baixada.
  2. No computador, vá em Folha QR → Conectar celular. Leia o QR no celular para preencher projeto, chave pública e sala. Também pode preencher manualmente.
  3. No novo aparelho, em Dados, entre com a mesma conta de conexão.
  4. Aguarde Sincronizado e confira os mesmos serviços no Painel.
  5. Instale o app, se necessário. No tablet compartilhado, ative Modo fábrica.

O QR não leva senha ou token de acesso. Cada aparelho precisa entrar na conta.

6. Faça o teste final

  1. Crie TESTE CONEXÃO no computador; espere Sincronizado. Confira o mesmo código e descrição no celular.
  2. Registre um trabalho em um aparelho e confira no Histórico do outro.
  3. Desligue a internet de um aparelho, crie outro teste e feche/reabra. Confira se permanece. Reconecte, espere Sincronizado e confira no outro.

A conferência automática ocorre aproximadamente a cada cinco segundos com o app aberto, sem formulário em preenchimento. A tela inicial confirma a gravação local; Sincronizado confirma a comunicação com o servidor.

Se aparecer conflito

O envio para até um administrador revisar. O botão Baixar as duas versões guarda os dados para conferência.

Manter servidor e guardar minha cópia conserva os itens do servidor nos conflitos e guarda a cópia local completa em Dados → Baixar cópias de recuperação. Alterações sem conflito são mantidas quando compatíveis. Consulte a cópia e reaplique manualmente o necessário.

Se houver dois serviços em andamento ou códigos repetidos, os serviços/eventos do servidor prevalecem na revisão; a cópia local permanece disponível para recuperar o restante.

Regras de uso

  • Um serviço em andamento por vez na sala. Não há vários cronômetros por operador nem contas individuais por crachá.
  • A senha administrativa protege ações na interface. É separada da conta de conexão, que dá acesso ao mesmo conjunto de dados nos aparelhos.
  • Alterações concorrentes em materiais, pedidos e estoque exigem revisão para evitar saldo incorreto.
  • Use uma janela por navegador. A segunda fica bloqueada para escrita.
  • No modo fábrica, a tela volta ao início após salvar localmente; o serviço em andamento continua ativo.
  • Leitor em modo teclado, com Enter ao final. Para QR, leitor 2D. Sem leitor, digite o código.
  • Novos códigos ganham um sufixo para evitar repetição entre aparelhos offline. Códigos e etiquetas antigos são preservados.

Verificação desta entrega

Testados dois navegadores simulados e funções PostgreSQL locais (PGlite): gravação com revisão, criação offline em paralelo, conflitos, recuperação, resposta perdida sem duplicar, reabertura offline, isolamento por conta, terminal e tela de celular.

Ainda precisa ser feito no seu ambiente: publicar o pacote, executar o SQL e validar seus aparelhos. Não houve acesso ao seu Supabase real nem teste com leitor físico.
