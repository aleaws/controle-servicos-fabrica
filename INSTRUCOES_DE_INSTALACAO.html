Um terminal compartilhado para a fábrica

Controle de Serviços da Manutenção — modo fábrica, leitor de códigos e instalação no tablet ou computador.

Como fica o uso

Ler o serviço → conferir → registrar a ação → voltar ao início.

Após iniciar, interromper, retomar, registrar uma etapa ou concluir, o aplicativo confirma a gravação no aparelho, limpa a seleção e prepara a próxima leitura. Um novo código não troca o serviço enquanto o apontamento estiver aberto.

Voltar ao início mantém o serviço em andamento. Para interrompê-lo, leia novamente a etiqueta e escolha a ação correspondente.

A tela volta ao início após 90 segundos sem interação, com aviso nos últimos 15 segundos. Campos ainda não salvos são descartados; os registros já gravados permanecem.

1. Prepare os dados desta cópia

Esta versão começa com registros e conexão próprios. Ela não busca automaticamente os dados da demonstração ou do V25.

Se quiser trazer uma cópia dos seus serviços, exporte um backup JSON na versão que você usa e importe em Dados → Importar backup somente neste novo aplicativo. A importação substitui os registros desta cópia; confira o destino antes de confirmar.

Os dados e a configuração anteriores ficam preservados. Crie a senha administrativa em Dados, ou use a senha do backup que você importou, antes de ativar Modo fábrica.

Envie ao GitHub os arquivos do aplicativo. Guarde backups JSON e registros da empresa fora do repositório público.

2. Crie um repositório separado

  1. No GitHub, escolha + → New repository.
  2. Nome: controle-servicos-fabrica. Para usar Pages no plano gratuito, marque Public. Ative Add README e clique em Create repository.
  3. Extraia este ZIP em seu computador. Mantenha o nome Controle_de_Servicos_da_Manutencao.html e a pasta icons.
  4. Dentro do novo repositório, clique em Add file → Upload files. Arraste o conteúdo da pasta extraída: os arquivos soltos e a pasta icons. O index.html deve aparecer na primeira lista do repositório, não dentro de outra pasta.
  5. Clique em Commit changes.
  6. Abra Settings → Pages. Em Source, escolha Deploy from a branch. Em Branch, selecione main e /(root). Clique em Save.
  7. Aguarde a publicação e abra o endereço apresentado pelo GitHub. Na conta aleaws, com esse nome de repositório, o endereço esperado é https://aleaws.github.io/controle-servicos-fabrica/.

Execute essas etapas no repositório controle-servicos-fabrica. Não altere a configuração Pages, o index ou os arquivos do repositório sistema-manutencao-v25.

3. Instale no tablet ou computador

  1. Abra o endereço online no Chrome ou Edge do aparelho.
  2. Clique em Instalar aplicativo. Se o navegador não abrir o convite, use a opção de instalação no próprio menu. No tablet, ela pode se chamar Adicionar à tela inicial.
  3. Abra o app pelo ícone criado. No mesmo endereço e perfil do navegador, os dados são compartilhados com a página.
  4. Na aba Dados, defina a senha administrativa. Depois clique em Modo fábrica. Esse modo fica ativo somente nesse aparelho e é lembrado ao reabrir.

A senha permite sair para a área administrativa. O modo fábrica organiza a tela; ele não substitui um sistema de autenticação e permissões no servidor.

4. Conecte e teste o leitor

  1. Conecte o leitor USB usando uma porta/adaptador compatível com o tablet, ou faça o pareamento Bluetooth.
  2. Configure o leitor em modo teclado (HID), com Enter no final da leitura. Esse ajuste costuma ser feito com os códigos do manual do fabricante.
  3. Na área administrativa, abra Folha QR → Etiquetas dos serviços — terminal da fábrica e imprima a etiqueta do serviço desejado.
  4. Ative o modo fábrica. O campo Código / QR do serviço recebe a leitura. Confira o código, a máquina e a descrição antes de apontar.

Para os QR desta versão, o leitor precisa ser 2D. Leitores que aceitam somente códigos de barras lineares não leem QR. O código também pode ser digitado, ou o serviço escolhido na lista.

O aplicativo aceita o código do serviço, o token existente e links de serviço com servico ou q. Uma etiqueta de conexão ou de tipo de operação não funciona como etiqueta de serviço no terminal.

O que esta versão mantém

O controle atual permite um serviço em andamento por vez. O novo modo muda o fluxo da tela, sem criar regras de trabalho simultâneo por operador.

A conexão Supabase existente é uma demonstração que envia o conjunto completo de dados. Vários aparelhos gravando simultaneamente podem sobrescrever alterações. Esta entrega não altera essa arquitetura: durante o teste, concentre os apontamentos em um único aparelho. Para uma implantação com vários operadores/aparelhos apontando ao mesmo tempo, é necessário acrescentar identificação dos operadores e controle de concorrência no servidor.

Após a primeira abertura online, os arquivos do aplicativo ficam disponíveis offline. Os dados continuam no aparelho. Instalação e funcionamento offline não significam que outro aparelho recebeu os registros; confira a conexão e os backups.

Verificação realizada

Testados no navegador: leitura simulada como teclado, gravação e retorno ao início, cliques repetidos, código inválido, bloqueio de troca durante formulário, inatividade, reabertura, falha de armazenamento e recuperação. Também foram verificados o Histórico/Relatório por mês, telas de celular/tablet e carregamento offline do pacote.

O teste de teclado simulado não substitui a conferência do leitor físico e do tablet que serão usados na fábrica.
